# 第四阶段周实验报告（对应原第 7–8 周）

**项目：**基于 AI 的 5G 网络 KPI 预测与异常检测系统  
**报告日期：**2026-10-23  
**本阶段任务：**程序集成、Streamlit 可视化、系统测试与优化、项目总结汇报

## 一、阶段目标

将既有 KPI 预测、异常检测、统计分析模块统一到可运行的 Web 系统，完善模型训练/推理、版本管理与用户文档，完成原八周计划第 7–8 周的工程化收尾。

## 二、完成工作及产出

1. **系统分层**：将源代码组织为 core、data、models、analysis、services、ui 六个子包，统一神经网络结构定义并去除重复的扁平入口。
2. **Web 展示**：基于 Streamlit 的总览、KPI 预测、模型评估、异常检测、KPI 关联分析及训练/推理页面已经成形。
3. **训练实验管理**：Web 可设置深度学习 Epoch、Batch Size、学习率、隐藏维度、时间窗口、样本上限及设备；异常检测可设置污染率和抽样量。新 DL/异常实验使用独立输出目录并保存 requested_parameters.json。
4. **模型推理**：从本地资源目录枚举权重版本，支持下一小时 KPI 预测；新增异常模型的 Web 候选标记与结果导出入口。
5. **训练日志**：以本机 WebSocket 将后台 stdout/stderr 实时送至页面，日志按容量或时间缓冲写入 current.log。
6. **修复问题**：处理重复实验标准化均值导致的报告合并冲突；修复 Windows GBK 日志不能打印 R² 的 UnicodeEncodeError。
7. **文档交付**：更新 README、USER_GUIDE、ARCHITECTURE；新增参数登记簿、收尾验收记录及技术报告，准备项目演示 PPT。

## 四、测试记录与阶段问题

**已观察到的本机事实：**Streamlit 曾成功启动；已有一轮模型注册/推理相关测试通过；在实际 LSTM 与传统 ML 训练中发现报错并作了代码层修复。

**尚需最终确认：**本轮最新分支的全部单元测试、Windows Web 完整点击流、权重加载后的真实数据预测、异常候选导出、性能计时、资源峰值和 GPU 状态。详见 `docs/FINAL_ACCEPTANCE.md`。缺失测试结果不得写为通过。

## 五、结果分析与讨论

- 主流程和 UI 已具备可操作的离线分析能力，但旧历史指标展示与最新模型权重并非自动一一对应，因此报告需保留版本说明。
- WebSocket 降低了日志在页面端的轮询开销；它优化交互和输出响应，不等于加速 PyTorch 训练。
- 深度学习和异常检测结果使用独立实验目录，有助于防止覆盖；传统 ML 的报告路径仍需后续优化。
- 无故障标注时，异常检测更适合描述为候选筛选，不适合声称已知诊断精度或确定根因。
