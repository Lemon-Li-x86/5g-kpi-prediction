# 数据集统计分析报告

## 1. 任务与目标

该任务为开源 5G 网络数据集的获取、数据质量检查、数据清洗、标准化与归一化，并构建可用于后续 KPI 预测的时间序列数据集。

主要工作包括：

1. 获取并整理 gotsf-ds 5G KPI 数据；
2. 对原始数据进行完整性和一致性审计；
3. 检查缺失值、重复值、无穷值、负值及时间连续性；
4. 将原始宽表数据转换为 beam-level 长表结构；
5. 按时间顺序划分训练集与测试集；
6. 使用 StandardScaler 进行标准化；
7. 使用 MinMaxScaler 进行归一化；
8. 输出预处理后的 KPI 数据集及预处理元数据。

## 2. 数据集概述

本项目使用 gotsf-ds 中的 5G 网络 KPI 训练数据。选取以下四类 KPI：

- `DLPRB`：Downlink Physical Resource Block 下行物理资源块相关指标；
- `DLThpVol`：Downlink Throughput Volume下行吞吐量相关指标；
- `DLThpTime`：Downlink Throughput Time下行吞吐时间相关指标；
- `MR_number`：Measurement Report Number数量相关指标。

每个 KPI 原始文件均包含：

- 840 个连续时间点；
- 2880 个 beam；
- 30 个基站；
- 90 个 cell；
- 1 个时间索引列。

单个 KPI 文件的原始数据规模为：

`840 × 2881`

其中 2880 列为 beam KPI，另 1 列为时间索引。

四个 KPI 文件采用完全相同的时间轴和 beam 结构，因此可以按照 `Time + base_station + cell + beam` 进行一一对应和合并。

## 3. 原始数据结构

原始 CSV 采用宽表形式，例如：

```text
Unnamed: 0 | 0_0_0 | 0_0_1 | 0_0_2 | ... | 29_2_31
0          | ...   | ...   | ...   | ... | ...
1          | ...   | ...   | ...   | ... | ...
```

其中第一列实际表示时间索引，但原始文件未提供列名，因此 Pandas 读取后显示为 `Unnamed: 0`。

预处理阶段首先将该列恢复为：

```text
Time
```

beam 列名采用：

```text
base_station_cell_beam
```

的编码方式。例如：

```text
12_2_31
```

被解析为：

```text
base_station = 12
cell = 2
beam = 31
```

## 4. 数据质量审计

在正式预处理前，对四个 KPI 文件分别进行了数据质量审计，包括：

- 时间索引完整性；
- 时间连续性；
- 重复时间检查；
- 完全重复行检查；
- 缺失值检查；
- 无穷值检查；
- 负值检查；
- beam 标识格式检查；
- 四个 KPI 文件的时间轴一致性；
- 四个 KPI 文件的 beam 结构一致性。

审计结果如下：

| 检查项 | DLPRB | DLThpVol | DLThpTime | MR_number |
|---|---:|---:|---:|---:|
| 时间点数量 | 840 | 840 | 840 | 840 |
| Beam 数量 | 2880 | 2880 | 2880 | 2880 |
| 缺失值 | 0 | 0 | 0 | 0 |
| 无穷值 | 0 | 0 | 0 | 0 |
| 负值 | 0 | 0 | 0 | 0 |
| 重复时间 | 0 | 0 | 0 | 0 |
| 完全重复行 | 0 | 0 | 0 | 0 |
| 时间缺口 | 0 | 0 | 0 | 0 |
| 非法 Beam 标识 | 0 | 0 | 0 | 0 |

四个数据文件的时间范围均为：

```text
Time = 0 ~ 839
```

相邻时间点间隔均为 1，说明时间轴连续。

此外，四个 KPI 文件的时间向量和 beam 列结构完全一致。

因此，原始数据未发现需要进行插值、删除或人工修复的缺失值、重复值或非法数值。

## 5. KPI 统计特征

原始 KPI 的主要统计结果如下：

| KPI | 均值 | 中位数 | 99% 分位数 | 最大值 | 0 值比例 |
|---|---:|---:|---:|---:|---:|
| DLPRB | 0.5409 | 0.1750 | 5.0773 | 41.0263 | 23.77% |
| DLThpVol | 0.3212 | 0.0952 | 3.5190 | 245.3746 | 31.76% |
| DLThpTime | 0.4252 | 0.1293 | 4.4634 | 84.2068 | 27.76% |
| MR_number | 0.6024 | 0.2273 | 5.0658 | 33.6660 | 20.15% |

四类 KPI 均存在较高比例的零值。考虑到 beam 在部分时间段可能没有对应业务活动，零值被视为有效网络状态，因此未删除。

从均值、中位数、99% 分位数和最大值之间的差异可以看出，各 KPI 分布均具有明显的右偏和长尾特征，即大多数观测值处于较低范围，但少量时间点会出现较大的 KPI 峰值。

其中 `DLThpVol` 的特征最明显：

- 中位数约为 0.0952；
- 99% 分位数约为 3.5190；
- 最大值达到约 245.3746。

这些较大的观测值不能仅根据统计幅度直接判定为错误数据，因为它们可能对应真实的高负载或突发业务场景。因此，本阶段未采用 3σ、IQR 等方法直接删除高值，而是保留所有满足物理约束的合法观测值。

## 6. 数据清洗与结构重构

### 6.1 时间字段处理

原始文件中的未命名时间索引列：

```text
Unnamed: 0
```

在预处理过程中被恢复为：

```text
Time
```

并验证其满足：

- 数值型；
- 无缺失；
- 无重复；
- 严格连续递增。

### 6.2 KPI 合法性检查

四类 KPI 均进行了以下检查：

- 非数值内容；
- NaN；
- 正负无穷；
- 负值。

审计结果均为 0，因此无需进行缺失值填补或非法值删除。

### 6.3 宽表转长表

原始数据使用一个 beam 对应一列的宽表结构。为了方便后续机器学习和时间序列特征构造，将数据转换为长表：

```text
Time | base_station | cell | beam | DLPRB | DLThpVol | DLThpTime | MR_number
```

转换后每一行表示：

> 某一时间点下某一个具体 beam 的四类 KPI 状态。

最终基础长表数据行数为：

`840 × 2880 = 2,419,200`

## 7. 时间序列划分

为了避免传统随机划分导致未来数据泄漏，本项目采用按时间顺序进行训练集和测试集划分。

划分方式为：

```text
Time 0–671   -> Train
Time 672–839 -> Test
```

其中：

- 训练时间长度：672 小时，即 4 周；
- 测试时间长度：168 小时，即 1 周。

对应数据行数：

| 数据集 | 时间范围 | 行数 |
|---|---|---:|
| Train | 0–671 | 1,935,360 |
| Test | 672–839 | 483,840 |

该划分保持了真实时间顺序，使后续模型始终使用过去数据训练，并在未来时间段进行测试。

## 8. 数据标准化

本项目采用 `StandardScaler` 对四类 KPI 进行标准化。

计算形式为：

```text
z = (x - mean) / standard_deviation
```

StandardScaler 仅使用训练集拟合，以避免测试期信息泄漏。

训练集拟合得到的参数如下：

| KPI | Train Mean | Train Standard Deviation |
|---|---:|---:|
| DLPRB | 0.536839 | 1.036266 |
| DLThpVol | 0.322617 | 1.096362 |
| DLThpTime | 0.422703 | 1.029392 |
| MR_number | 0.597422 | 1.039071 |

生成的新特征为：

```text
DLPRB_z
DLThpVol_z
DLThpTime_z
MR_number_z
```

验证结果表明，训练集标准化后：

```text
mean ≈ 0
standard deviation = 1
```

实际训练集均值均处于约 `10^-9` 数量级，可视为浮点数计算误差范围内的 0。

## 9. 数据归一化

除 StandardScaler 外，本项目同时使用 `MinMaxScaler` 生成 0–1 归一化表示。

计算形式为：

```text
x_normalised = (x - min) / (max - min)
```

MinMaxScaler 同样仅在训练集上进行拟合。

训练集拟合范围如下：

| KPI | Train Minimum | Train Maximum |
|---|---:|---:|
| DLPRB | 0.0000 | 41.0263 |
| DLThpVol | 0.0000 | 245.3746 |
| DLThpTime | 0.0000 | 84.2068 |
| MR_number | 0.0000 | 33.6660 |

生成的新特征为：

```text
DLPRB_mm
DLThpVol_mm
DLThpTime_mm
MR_number_mm
```

训练集归一化后的最小值均为 0，最大值约为 1。

当前测试集归一化最大值分别为：

| KPI | Test Normalised Maximum |
|---|---:|
| DLPRB | 0.8503 |
| DLThpVol | 0.1214 |
| DLThpTime | 0.4814 |
| MR_number | 0.9601 |

测试集仍使用训练集拟合得到的 MinMax 参数，不重新计算测试集最小值或最大值，从而避免数据泄漏。


### 原始 KPI

```text
DLPRB

```

### 数据集划分

```text
split
```

### StandardScaler 特征

```text
DLPRB_z

```

### MinMaxScaler 特征


## 11. 结论

截至目前，完成了开源 5G KPI 数据集的获取、审计、清洗、结构重构、标准化、归一化和时间序列数据集构建。

主要结果如下：

1. 完成四类 KPI 数据的完整性审计；
2. 未发现缺失值、无穷值、负值、重复时间或时间缺口；
3. 保留合法的零值和高值观测，避免删除可能对应真实网络状态的数据；
4. 将 4 个宽表 KPI 文件转换为统一的 beam-level 长表；
5. 构建 2,419,200 行的 KPI 时间序列基础数据集；
6. 使用按时间顺序的训练集/测试集划分，避免未来信息泄漏；
7. 分别生成 StandardScaler 标准化特征和 MinMaxScaler 归一化特征；
8. 两类 scaler 均仅在训练集上拟合；
9. 最终得到包含原始、标准化和归一化 KPI 的 17 列数据集。

该数据集可直接作为第 4 周传统机器学习 KPI 预测模型的基础输入，并可进一步构造 lag、周期和历史窗口等时间序列特征。
